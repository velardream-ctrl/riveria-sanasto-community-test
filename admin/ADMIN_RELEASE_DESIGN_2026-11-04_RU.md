# Sanastoyhteisö 3.0 — админ-центр и обновление одним файлом
Дата: 2026-11-04. Статус: SPEC / STAGING ONLY — НЕ активировано на рабочем сайте.

## Решение владельца
- **НЕ публиковать** текущую тестовую сборку на https://sanastoyhteiso.github.io/, пока админ-панель и мониторинг не будут реализованы и проверены.
- `Данные` — исключительно личный раздел ученика, без админ-метрик и кнопок отладки.
- Админ-центр — отдельная ссылка `/admin/`, обнаруживаемая только после проверки серверно выданной Firebase admin-роли. Сам маршрут не секрет; каждый API-запрос защищён серверными правилами. Никакого предоставления роли через URL, email, localStorage, параметры браузера или клиентский код.
- FI / EN / RU, автоматическое определение языка, совместимость iOS 12, минимальное вмешательство в утверждённый учебный интерфейс.

## Реальные статусы
1. `OK` — сбор ошибок функционирует, есть свежая серверная отметка, проверки систем зелёные, в заданном окне нет открытых критических проблем.
2. `Проблема` — конкретный подтверждённый сбой; число и доля затронутых установок, разрез браузер/версия, момент последнего появления.
3. `Нет данных` — мониторинг выключен, не получает события, нет соединения или агрегаты просрочены; никогда не подменять нулём ошибок.
4. Сервисные показатели: вход/подтверждение email, Firestore permissions/квота, offline replay, queue stuck, повторный вход, localStorage/IndexedDB quota, service worker и cache version, версия словаря, ошибки публикации/отката, последняя подтверждённая резервная копия.

## Ошибки пользователей: минимально необходимая телеметрия
- Клиент фиксирует нормализованные код ошибки/тип, затронутый модуль (без значений из форм), severity, версию сборки, семейство/основную версию браузера, ОС, время и online/offline. Ограниченный объём, без свободных строк и raw stack.
- Нет email, ФИО, UID, токенов, полных URL/query, пользовательских слов/ответов, записей Mediatri, пациентских данных, исходного userAgent; псевдонимизированный краткоживущий идентификатор с ротацией только если он необходим для dedup, без публичных индивидуальных профилей. По умолчанию предпочесть агрегаты.
- При offline — ограниченная очередь событий на устройстве, отправка после восстановления связи, dedup, rate limit, TTL и защита от переполнения; ошибки самой отправки не должны ломать обучение.
- Минимизация персональных данных, прозрачное уведомление о диагностике и правовое основание/срок хранения согласно GDPR. Запрещён экспорт пользовательских ответов и чтение приватных слов из админ-панели.
- Firestore: входящий `telemetry_reports` при строгих правилах create-only с проверкой схемы, ограничений и авторизации; READ администратору через `request.auth.token.admin == true`; анонимные или незарегистрированные посетители не должны получать доступ к чужим событиям. Защита от злоупотребления и квот должна быть на сервере/в инфраструктуре.
- Защищённая задача агрегации выпускает небольшие `admin_metrics` (24 ч / 7 дней), диагностические коды/браузеры/версии, без доступа админа к личным учебным данным. Не выдавать «ОК» без heartbeat + полноты входящих данных.
- Проверять два аккаунта (ученик/админ), два устройства, отказ в доступе обычного пользователя, offline, Firestore Rules emulator, quota, совместимость Safari 12.

## Отдельный маршрут /admin/
Разделы: Обзор / Ошибки / Браузеры и устройства / Синхронизация / Резервные копии / Обновления / Аудит.
- В обзоре: свежесть мониторинга, статус по подсистемам, версия production и test, число активных учеников и ошибки только агрегированно.
- В ошибках: код, встречаемость, первое и последнее появление, затронутые браузеры/версии, resolved/unresolved, ссылку на исправляющий GitHub PR; не показывать идентифицирующие сведения.
- Прозрачное управление статусом исправлено/проверить/открыто; сами ошибки не удалять бесследно. Ведение истории действий админа.
- Настоящее назначение admin-роли — только привилегированным сервером через Firebase Admin SDK, не клиентским JavaScript.

## Обновление одним файлом
Пользователь получает один `.zip` **пакет выпуска**, подготовленный разработчиком:
`manifest.json` (schemaVersion, packageId, target repo, expected baseCommit, releaseType, changed files и SHA-256), а также только изменённые файлы.
НЕ использовать в ZIP токены, service account, passwords, Firebase Rules, личные данные или копии приватных словарей.

Безопасный поток:
1. Администратор открывает `/admin/ → Обновления` и выбирает файл.
2. Клиент делает предварительную проверку; **защищённый backend** повторяет все проверки (строгий список путей, лимиты размеров, SHA-256, корректный baseCommit, отсутствие обходов `../`, запрет удаления, зависимостей, бинарного/исполняемого содержимого без code review).
3. Защищённый backend, используя ограниченную GitHub App installation permission, создаёт ветку/PR в **TEST** репозитории; GitHub токены никогда не размещаются в JavaScript GitHub Pages.
4. CI: проверка правил, совместимости синтаксиса iOS 12, авторизации, телеметрии, миграций, build, тест двух аккаунтов и smoke; отчет в админ-центре.
5. Администратор явно подтверждает выпуск на основной домен; GitHub protected environment/review, staging deployment, резервная копия и проверка health. Публикация только после всех gates.
6. Доступен откат к предыдущему commit с проверкой cache/service worker и сохранностью пользовательских данных. Обновление программы не должно автоматически очищать Firestore/IndexedDB.

`manifest.json` и валидатор добавлены в этой ветке только как подготовительный контракт; **загрузка/публикация с веб-сайта пока не работает**. Простой zip-файл не должен исполняться в браузере.

## Бесплатный план и зависимости
- GitHub Pages статический: не хранит серверный токен и не умеет сам безопасно записывать в репозиторий.
- Firebase Spark не включает Cloud Functions. Не менять тариф и не включать платёжную информацию без отдельного разрешения.
- Для функции реальной «Загрузить ZIP → открыть PR» потребуется backend (например, изолированный GitHub App service / Cloudflare Worker с секретом), его размещение, аутентификация и аудит; либо оставить ручное подтверждение PR через GitHub без сервера.
- Для *содержимого словаря* (не JS приложения) можно в будущем выбрать отдельный админский поток через Firestore с проверкой схемы/модерацией и резервом, без обновления всего GitHub Pages.
- При невыполненных условиях блокировать «Опубликовать», показывать причину. **Не создавать фальшивые «ОК» и «Сайт обновлён».**

## Условия переноса на основной домен
- Подтверждённая реальная admin роль для владельца; обычные пользователи не видят админ-пункт и не могут читать диагностику через API.
- Подключены безопасная доставляемая диагностика + агрегаты и реальный статус здоровья (OK / Проблема / Нет данных), проверен поток ошибки с Safari и намеренно сломанного теста.
- Работает процесс одного файла сначала в test, с CI, подтверждением release и обратимым откатом; пробный релиз на test.
- Тесты двух реальных аккаунтов и iOS 12, подтверждение существующих UID и полного словаря, безопасный выпуск/миграция без потерь остальных учеников.
